# 화면 맞춤 4단계 UI 검증 기록

검증일: 2026-10-26

## 변경 범위

- static/index.html: 촬영 / 사진·재료 확인 / 메뉴 추천 / 요리 화면을 분리.
- static/style.css: 뷰포트 높이를 사용하는 반응형 그리드. 큰 최소 높이와 문서 세로 스택 제거.
- static/app.js: 단계 이동, 동일 카메라 스트림을 사용하는 제스처 미리보기, 화면 크기 기반 레시피·인식 설명·메뉴 설명 페이지 분할, 새 제스처 명령 매핑.
- README 및 브라우저 테스트 업데이트. 기존 Python 서버·AI 처리·모델 설정과 core.js의 타이머/제스처 상태 머신은 그대로 유지.

## 실행 결과

- Python 백엔드 회귀 검사 23개 통과.
- Node 핵심 상태 머신 검사 7개 통과.
- 실제 Chromium에서 가상 웹캠 촬영 → 재료 확인 → 메뉴 추천 → 선택 → 레시피북 흐름 통과.
- 손바닥 모드 전환, 검지 시간 설정·추가, 엄지 위/아래의 페이지·시작/정지 연결 통과. 인식 결과는 모의 응답.
- 브이·주먹·I Love You는 명령을 실행하지 않는 것을 확인.
- 모드 전환 후 같은 손모양을 유지해도 명령이 연속 실행되지 않는 것을 확인.
- 시간 직접 입력, 감소·초기화·단위 변경, 페이지 이동 중 타이머 유지, 새로고침 복원, 완료 표시, JSON 다운로드 통과.
- 요리 화면 밖에서는 제스처 명령을 실행하지 않음. 재료 수정 시 확인 체크와 메뉴 무효화.
- 1920×1080, 1536×864, 1366×768, 1280×720, 1024×768, 800×600, 768×1024, 390×844, 375×667, 844×390의 네 단계 화면에서 문서 가로/세로 넘침과 주요 패널·버튼 잘림 없음.
- 타이머 모드 및 24시간 표시에서도 같은 크기 검사 통과.
- 긴 재료 목록 30개, 주의사항 10개, 긴 조리 설명을 넣고 데스크톱·휴대전화·가로 화면에서 세부 페이지를 모두 검사. 문자 손실과 레시피 패널 넘침 없음.
- 긴 인식 설명의 문자 보존 및 긴 메뉴 설명의 화면 맞춤 확인.
- 한글 글꼴을 설치한 Chromium 렌더링으로 데스크톱과 작은 화면 배치를 육안 확인.

## 실제 장치에서 남은 확인

- 이 환경에는 사용자의 웹캠과 MediaPipe 모델이 없으므로 실제 손 인식률을 측정하지 않았습니다.
- VLM/LLM/YOLO 실제 추론을 다시 검증하지 않았습니다. UI 검사는 고정 데모 결과를 사용합니다.
- Windows 기본 글꼴과 브라우저 배율에 따라 줄바꿈은 달라질 수 있습니다. 레시피 페이지 분할은 렌더링된 높이를 기준으로 다시 계산합니다.
- 편집 중인 긴 textarea 입력 내용에는 자체 스크롤이 생길 수 있습니다. 앱 전체와 주요 표시 패널은 스크롤 대신 화면 맞춤 및 페이지 이동을 사용합니다.
- 브이/주먹을 손바닥/검지 중심으로 바꿨지만 실제 인식은 조명·손 방향·거리·모델 성능에 영향을 받습니다.

## 재현

```cmd
python -m unittest discover -s source\tests -p test_backend.py
node --test source\tests\test_core.cjs
python source\app.py --demo --port 8765
```

별도 터미널에서 Playwright/Chromium 설치 후:

```cmd
node source\tests\test_ui.cjs
node source\tests\test_layout.cjs
```

`test_dom.cjs`는 화면 치수를 측정할 수 있는 실제 브라우저 통합 검사로 연결됩니다.
