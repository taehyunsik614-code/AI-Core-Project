# 손끝 없이 · 비접촉 AI 레시피북 v1.2.0

## 기존 사용자의 적용 순서

1. 실행 중인 서버 창에서 Ctrl+C를 누릅니다.
2. 기존 source 폴더를 source_backup으로 이름을 바꿉니다.
3. 이 ZIP을 별도 임시 폴더에 풉니다. 압축 안의 source 폴더를 기존 models와 같은 위치에 옮깁니다.
4. source/app.py가 바로 있어야 합니다. source/source/app.py가 되면 잘못 배치한 것입니다.
5. 기존 가상환경과 models는 그대로 사용합니다. 추가 패키지 설치는 필요 없습니다.

Windows CMD에서:

```cmd
cd /d C:\Users\SSAFY\Downloads\kitchen_book\kitchen_book
.venv\Scripts\activate
python source\app.py
```

가상환경이 상위 kitchen_book에 있으면 `..\.venv\Scripts\activate`로 활성화합니다.
또는 `source\run_windows.bat`을 실행하면 현재/상위 위치의 가상환경을 찾습니다.
브라우저 http://127.0.0.1:8000 에서 Ctrl+F5. 오른쪽 위 LOCAL AI v1.2.0 확인.

## 네 화면 사용 흐름

1. **촬영**: 카메라 중심 큰 화면. 사진 찍기 또는 직접 입력.
2. **재료 확인/수정**: 실제 전송 사진과 후보 목록 비교, 재료 수정, 확인 체크, 요청 입력.
3. **메뉴 추천**: 확인한 재료로 세 메뉴 표시. 메뉴를 누르면 레시피를 생성합니다.
4. **레시피북**: 위쪽 제스처 안내, 왼쪽 큰 책, 오른쪽 실시간 카메라와 타이머.

왼쪽 하단 뒤로가기: 2→1 재촬영, 3→2 재료 수정, 4→3 메뉴 재선택.
추론 중에는 중복 실행과 뒤로가기를 잠시 잠급니다. 오류가 나면 다시 사용할 수 있습니다.
재료 인식 오류 시 2번 화면에서 직접 입력할 수 있습니다. 메뉴 오류 시 다시 시도 버튼,
레시피 오류 시 같은 메뉴를 다시 누르면 됩니다. 추론 실패를 데모 레시피로 숨기지 않습니다.
좁은 휴대폰 화면(430px 이하)에서는 책과 카메라가 세로로 배치됩니다.
현재 레시피와 타이머는 복원되지만 시작 화면은 항상 촬영입니다.

## 느려지는 구조를 바꾼 부분

| 항목 | 이전 기본값 | 1.2.0 기본값 |
|---|---|---|
| VLM 입력 긴 변 | 896px | 448px |
| 사진 분석 | 관찰 + 재확인 두 번 | 관찰 한 번 + 사용자 확인 |
| 실패 자동 재시도 | 최대 2회 | 1회, 오류를 표시하고 사용자가 재시도 |
| 재료 출력 한도 | 1800토큰 | 700토큰 |
| 메뉴 출력 한도 | 3000토큰 | 600토큰 |
| 레시피 출력 한도 | 3000토큰 | 1600토큰, 4~6단계 |
| 메뉴/레시피 JSON | 생성 후 검증 | 생성 시 JSON 스키마 제약 + 생성 후 검증 |
| 컨텍스트 | 8192 | 4096 |
| 같은 입력 | 다시 추론 | 최근 24개 성공 결과 메모리 캐시 |
| 제스처 추론 | 켜두면 계속 | 레시피 화면이며 AI 작업 중이 아닐 때만 |

캐시는 재료/요청/선택 메뉴 전체를 키로 구분합니다. 실패는 캐시하지 않습니다.
서버 재시작 시 캐시는 비워집니다. 처음 모델을 불러오는 시간은 여전히 필요합니다.
메모리 사용을 위해 큰 모델 하나만 유지하므로 재촬영으로 VLM에 돌아가면 모델 전환이 필요합니다.
JSON 제약은 괄호 오류 가능성을 낮추지만 토큰 잘림/내용 오류까지 없애지는 못합니다.
작아진 이미지에서는 작은 재료를 놓칠 수 있으므로 밝게 가까이 촬영하고 2번 화면에서 수정하세요.
이 환경에서는 실제 GGUF 모델과 사용자 PC가 없어 속도 배수/완료 초를 측정하지 않았습니다.

## 설정 (선택 사항)

기본값으로 먼저 실행하세요. 아래 환경변수는 서버 실행 전에 설정합니다.

- KITCHEN_IMAGE_SIDE: 서버 입력 긴 변 224~896, 기본 448. 브라우저도 448로 전송하므로 실제 고해상도 사용 시 app.js의 capture() 호출 해상도도 변경해야 합니다.
- KITCHEN_VERIFY_IMAGE=1: 사진 두 번째 검증 활성화. 더 느려집니다.
- KITCHEN_AI_ATTEMPTS=2: 출력 오류 자동 재시도 활성화. 더 느려질 수 있습니다.
- KITCHEN_CONTEXT: 기본 4096.
- KITCHEN_THREADS: CPU 스레드 수, 기본 최대 6.
- KITCHEN_GPU_LAYERS: 기본 0. GPU 지원 llama.cpp 빌드 및 VRAM이 있을 때만 설정합니다.

## 손동작 조작표

각 동작을 약 **0.9초** 유지합니다. 인식 신뢰도 0.65 이상일 때만 처리하며 통신 지연으로 유지 시간이 끊기면 다시 유지해야 합니다.

| 손 모양 | 책 모드 | 타이머 모드 |
|---|---|---|
| 👍 엄지 위 | 다음 페이지 | 시작·재개 |
| 👎 엄지 아래 | 이전 페이지 | 일시정지 |
| ✌️ V | 타이머 모드 | 책 모드 |
| ✊ 주먹 | 이 단계 시간 설정 → 타이머 모드 | 현재 설정값으로 초기화 |
| ☝️ 검지만 펴기 | 동작 없음 | 시간 증가 |
| 🖐 손바닥 | 동작 없음 | 시간 감소 |
| 🤟 엄지·검지·새끼 | 동작 없음 | 시간 단위 전환 |

시간 단위: 1분 → 5분 → 1초 → 10초 → 1분. 시간 조절 시 자동 일시정지되며 조절한 값이 초기화 기준이 됩니다. 타이머는 1개이고 최대 24시간입니다. 현재 모드는 손동작 안내 제목 옆에 표시됩니다.

레시피 저장/불러오기는 JSON을 사용합니다. 현재 레시피·페이지·타이머는 브라우저에도 저장되며 새로고침 시 종료시각을 복원합니다. 브라우저를 닫거나 PC가 잠든 상태의 알람은 보장하지 않습니다. 소리를 들으려면 이 페이지를 열어 두고 한 번은 시작/제스처 켜기 버튼을 누르세요.

## 처음 설치할 때만 (Windows CMD / Python 3.12)

**source와 models가 있는 폴더**에서 실행합니다.

```cmd
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -r source\requirements.txt
python source\app.py --check
python source\app.py
```

requirements에는 공식 CPU wheel 인덱스와 llama-cpp-python의 바이너리 설치 옵션을 넣었습니다. 호환 wheel이 없으면 직접 컴파일하지 않고 설치 오류를 표시합니다. 기존에 설치한 사용자는 패키지를 다시 설치할 필요가 없습니다.

모델 파일명이 다르면 CMD에서 실제 이름을 지정할 수 있습니다.

```cmd
set "KITCHEN_LLM=실제_LLM파일.gguf"
set "KITCHEN_VLM=실제_VLM파일.gguf"
set "KITCHEN_PROJECTOR=실제_mmproj파일.gguf"
set "KITCHEN_GESTURE=gesture_recognizer.task"
python source\app.py
```

모델 폴더 자체는 `KITCHEN_MODELS`로 지정할 수 있습니다. VLM은 Qwen2.5-VL에 맞는 본체와 projector 조합을 사용해야 합니다. 다른 아키텍처는 이름만 바꾸는 것으로 호환되지 않습니다. CPU 기본 최대 6개 스레드이며 `KITCHEN_THREADS`로 조절합니다. GPU 지원 빌드가 있는 경우에만 `KITCHEN_GPU_LAYERS`를 지정하세요. 기본은 0입니다.

Linux에서는 `python3.12 -m venv .venv`, `.venv/bin/python -m pip install -r source/requirements.txt`, `.venv/bin/python source/app.py`를 사용합니다. 경로는 실행 폴더가 아닌 소스 파일 위치를 기준으로 계산합니다.
