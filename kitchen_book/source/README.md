# 손끝 없이 · 화면 맞춤 4단계 레시피북

웹캠 촬영 → 재료 후보 관찰·재확인 → 사용자 확인 → LLM 메뉴 추천 → 레시피북 생성 → 손동작 페이지·타이머 조작.


## 이번 수정: 한 화면에 맞는 4단계 UI

1. 재료 촬영: 화면 크기에 맞춘 큰 웹캠과 촬영 버튼.
2. 재료 확인: 실제 촬영 사진과 재료 수정 입력창을 같은 화면에 표시.
3. 메뉴 추천: 메뉴 세 개를 한 화면에 표시. 긴 추천 설명은 카드 안에서 이전/다음으로 읽기.
4. 요리: 손동작 안내, 레시피북, 제스처 웹캠, 타이머를 동시에 표시.

화면 높이에 맞춰 패널 크기를 조절하며 긴 레시피와 인식 설명은 페이지를 나눕니다. 단순히 화면 밖 내용을 숨기거나 전체 화면을 축소하지 않습니다. 편집용 입력창은 긴 입력 시 자체 스크롤을 사용할 수 있습니다.

## 기존 사용자: 이번 수정본 적용

1. 실행 중인 서버의 터미널에서 **Ctrl+C**로 종료합니다.
2. 이 ZIP을 풀면 바로 보이는 **static 폴더의 index.html, style.css, app.js, core.js**를 기존 프로젝트의 **source\static** 폴더에 덮어씁니다. 이번 기능 수정은 프런트엔드에만 있습니다. 다른 버전의 YOLO/AI 서버를 사용 중이어도 Python 파일은 바꾸지 않아도 됩니다.
3. **models 폴더와 .venv는 그대로 사용**합니다. 모델이나 패키지 재설치는 필요 없습니다.
4. 기존 가상환경의 프로젝트 폴더에서 실행합니다.

```cmd
python source\app.py
```

브라우저에서 **http://127.0.0.1:8000** 접속 후 **Ctrl+F5**로 새로고침합니다. 위쪽에 `01 재료 촬영 / 02 재료 확인 / 03 메뉴 추천 / 04 요리 시작`이 보이면 적용된 것입니다. 실제 모델을 사용하려면 `--demo` 없이 실행합니다.

전체 소스는 첨부받은 원본을 기반으로 함께 포함했습니다. 기존 모델 경로, AI 처리, 서버 API는 변경하지 않았습니다.

## 이번 변경점

### 촬영·재료 인식

- 카메라 요청 해상도를 최대 1280×720 수준으로 높이고, 실제 입력은 긴 변 최대 896px로 전달합니다. 장치가 제공하는 해상도가 더 낮으면 그 해상도를 사용합니다.
- 촬영 화면은 첫 단계의 남은 화면 공간을 채우고, 실제 분석 사진은 두 번째 단계에서 확인합니다.
- **촬영 범위 → 가운데만 촬영**은 중앙의 일부를 잘라 분석하여 배경을 줄입니다. 실제 잘린 사진을 결과 영역에서 확인하세요.
- 첫 VLM 호출에서 재료 후보와 관찰 특징을 받습니다. 같은 사진을 다시 전달해 후보를 재확인하고, 재확인에서 부정된 후보는 확인 필요 항목으로 분리합니다.
- 프롬프트의 특정 식재료 예시를 없앴고 VLM temperature를 0으로 설정했습니다.
- 결과의 특징 설명도 모델의 추정이며 정확도를 보증하는 증거가 아닙니다. 같은 모델이 두 번 모두 틀릴 수 있습니다. 사진과 목록을 비교하여 직접 수정한 뒤 **재료 목록 확인란**을 체크해야 메뉴 추천이 가능합니다.
- 재촬영 시 이전 재료와 추천 메뉴를 지워 과거 결과가 새 사진의 결과로 남지 않게 했습니다. 재료를 수정하면 확인 체크와 메뉴도 해제됩니다.
- 추가 학습은 필요 없습니다. 두 단계 VLM 호출로 인해 기존보다 시간이 더 걸릴 수 있습니다. 실제 정확도 개선 정도는 보유 모델과 촬영 환경으로 평가해야 합니다.

### 타이머

- 조리 설명에 명시된 `3분`, `1분 30초`, `2~3분` 등을 읽어 `timer_seconds`가 누락되거나 0 또는 다른 값이어도 보완합니다. 이전 저장 레시피에도 같은 처리를 합니다.
- 범위는 상한(예: 2~3분 → 3분)을 사용합니다. 한 단계에 서로 다른 행동 시간이 여러 개 있으면 첫 번째 시간 표현을 사용하며 별개 행동의 시간을 합치지 않습니다. 실제 설명을 확인하고 필요하면 조절하세요.
- 명시된 시간도 모델의 시간 값도 없으면 임의 시간을 만들지 않습니다. 손동작으로 직접 설정할 수 있습니다.
- **실행 중인 타이머가 없을 때** 조리 페이지를 넘기면 해당 단계 시간이 자동으로 설정됩니다. 자동 시작은 하지 않습니다.
- **실행 중인 타이머는** 페이지를 넘겨도 계속 유지합니다. 기존 타이머를 일시정지한 후 현재 단계에서 검지만 펴면 새 단계 시간을 설정합니다.
- 시간이 없는 단계에서도 검지만 펴서 타이머 모드를 열 수 있습니다. 검지로 시간을 추가한 뒤 시작하세요.
- 서로 다른 손 모양을 각각 유지하면 손을 내리지 않아도 다음 명령을 받습니다. 같은 동작을 계속 유지하면 반복하지 않으며, 같은 명령을 다시 실행하려면 손을 잠시 내려 주세요.

### 화면

- 모니터에서는 안내–레시피북–웹캠·타이머 순서로 배치합니다.
- 폭이 좁으면 손동작 안내를 위로 옮기고, 책과 웹캠·타이머는 나란히 유지합니다.
- 긴 레시피는 글자를 지나치게 줄이지 않고 세부 페이지로 나눕니다. 동일 조리 단계 안의 세부 페이지를 넘길 때 타이머는 재설정되지 않습니다.
- 요리 화면을 벗어나면 제스처 명령을 중지하지만 실행 중인 타이머는 유지합니다.
- 촬영 웹캠과 제스처 웹캠은 같은 카메라 스트림을 공유합니다. 웹캠을 껐더라도 요리 화면의 제스처 켜기를 누르면 카메라 연결을 요청합니다.

## 사용 순서

1. **웹캠 켜기 → 사진 찍고 재료 찾기**. 재료를 가까이, 밝게 촬영합니다.
2. 촬영 사진과 재료 후보·특징을 비교하고 틀린 이름을 수정합니다. 직접 입력으로 시작해도 됩니다.
3. **재료 목록 확인란**을 체크한 뒤 메뉴를 추천받습니다.
4. 메뉴를 선택하여 레시피북을 생성합니다.
5. **제스처 켜기**를 누르고 준비 페이지에서 조리 단계로 넘깁니다.
6. 시간이 있는 단계는 자동 설정됩니다. **🖐 타이머 모드 → 👍 시작**으로 실행합니다.
7. 완료 후 **🖐 책 모드 → 👍 다음 단계**로 넘기면 다음 단계 시간이 자동 준비됩니다.

## 손동작 조작표

각 동작을 약 **0.9초** 유지합니다. 인식 신뢰도 0.65 이상일 때만 처리하며 통신 지연으로 유지 시간이 끊기면 다시 유지해야 합니다.

| 손 모양 | 책 모드 | 타이머 모드 |
|---|---|---|
| 👍 엄지 위 | 다음 페이지 | 시작·재개 |
| 👎 엄지 아래 | 이전 페이지 | 일시정지 |
| 🖐 손바닥 펴기 | 타이머 모드 | 책 모드 |
| ☝️ 검지만 펴기 | 이 단계 시간 설정 → 타이머 모드 | 시간 증가 |

브이·주먹·엄지/검지/새끼 동작은 명령에서 제외했습니다. 감소·초기화·조절 단위 변경은 타이머의 버튼을 사용합니다. 주먹의 초기화 기능은 버튼으로 유지하고, 책 모드의 단계 시간 설정 기능은 검지로 옮겼습니다.


시간 단위: 1분 → 5분 → 1초 → 10초 → 1분. 시간 조절 시 자동 일시정지되며 조절한 값이 초기화 기준이 됩니다. 타이머는 1개이고 최대 24시간입니다. 현재 모드는 손동작 안내 제목 옆에 표시됩니다.

레시피 저장/불러오기는 JSON을 사용합니다. 현재 레시피·페이지·타이머는 브라우저에도 저장되며 새로고침 시 종료시각을 복원합니다. 브라우저를 닫거나 PC가 잠든 상태의 알람은 보장하지 않습니다. 소리를 들으려면 이 페이지를 열어 두고 한 번은 시작/제스처 켜기 버튼을 누르세요.

## 처음 설치할 때만 (Windows CMD / Python 3.12)

**source와 models가 있는 폴더**에서 실행합니다.

```cmd
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -r source\requirements.txt
python source\app.py --check
python source\app.py
```

requirements에는 공식 CPU wheel 인덱스와 llama-cpp-python의 바이너리 설치 옵션을 넣었습니다. 호환 wheel이 없으면 직접 컴파일하지 않고 설치 오류를 표시합니다. 기존에 설치한 사용자는 패키지를 다시 설치할 필요가 없습니다.

모델 파일명이 다르면 CMD에서 실제 이름을 지정할 수 있습니다.

```cmd
set "KITCHEN_LLM=실제_LLM파일.gguf"
set "KITCHEN_VLM=실제_VLM파일.gguf"
set "KITCHEN_PROJECTOR=실제_mmproj파일.gguf"
set "KITCHEN_GESTURE=gesture_recognizer.task"
python source\app.py
```

모델 폴더 자체는 `KITCHEN_MODELS`로 지정할 수 있습니다. VLM은 Qwen2.5-VL에 맞는 본체와 projector 조합을 사용해야 합니다. 다른 아키텍처는 이름만 바꾸는 것으로 호환되지 않습니다. CPU 기본 최대 6개 스레드이며 `KITCHEN_THREADS`로 조절합니다. GPU 지원 빌드가 있는 경우에만 `KITCHEN_GPU_LAYERS`를 지정하세요. 기본은 0입니다.

Linux에서는 `python3.12 -m venv .venv`, `.venv/bin/python -m pip install -r source/requirements.txt`, `.venv/bin/python source/app.py`를 사용합니다. 경로는 실행 폴더가 아닌 소스 파일 위치를 기준으로 계산합니다.

## 데모와 검증

```cmd
python source\app.py --demo
```

데모는 **고정 재료·추천·레시피 예시**입니다. 실제 사진 인식 확인에는 사용하지 마세요. 제스처는 데모에서도 MediaPipe와 실제 task 모델이 있어야 작동합니다.

```cmd
python -m unittest discover -s source\tests -v
node --test source\tests\test_core.cjs
```

Node.js는 개발 테스트에만 필요하며 앱 실행에는 필요 없습니다. 선택적 화면 테스트는 데모 서버를 8765 포트로 실행한 뒤 Playwright/Chromium 환경에서 `node source/tests/test_ui.cjs`, `node source/tests/test_layout.cjs`로 레이아웃을 검사합니다. `test_dom.cjs`는 실제 브라우저 통합 검사로 연결됩니다. 설치는 `npm install --no-save playwright`, `npx playwright install chromium`입니다. 테스트는 가상 웹캠·고정 AI 결과·모의 제스처를 사용합니다. 보유 모델의 실제 정확도와 물리적인 손 인식은 대상 PC에서 확인해야 합니다.

사진은 파일로 저장하지 않고 로컬 메모리에서 처리합니다. 인식 재료·레시피·타이머는 브라우저 localStorage에 저장됩니다. 선택적인 음성 입력은 브라우저 서비스가 처리하며 네트워크를 사용할 수 있습니다. 이미지에서 신선도나 내부 온도를 측정하는 기능은 없습니다. 이 서버는 한 PC·한 사용자를 위한 localhost 앱입니다.
